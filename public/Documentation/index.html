Frontend de la aplicación

Construido con React + Vite para un desarrollo rápido y moderno. Se utilizó JavaScript, JSX y CSS modular, siguiendo principios de diseño responsivo.

Tecnologías

JavaScript (ES6+), JSX, CSS modular, Flexbox, Grid.

Librerías principales

React Router, Axios, React Hook Form, React Modal.

📌 Pasos para levantar el Frontend

  1. Asegurar Node.js instalado (nodejs.org).
  2. Navegar al directorio del frontend: cd frontend-happy-pets.
  3. Instalar dependencias: npm install.
  4. Iniciar servidor de desarrollo: npm run dev (generalmente en http://localhost:3001).
  5. Build para producción: npm run build (genera carpeta dist/).
⚠️ Importante: El frontend necesita el backend activo para funcionar completamente. Si el backend no está levantado, solo se mostrará la pantalla de Login y al intentar autenticar aparecerá un error de conexión.

Backend (Node.js + MySQL)

Backend desarrollado con Node.js, Express y MySQL. Maneja la lógica de negocio, autenticación y persistencia de datos.

📌 Pasos para levantar el Backend

  1. Node.js instalado.
  2. Ir al directorio del backend: cd backend-happy-pets.
  3. Instalar dependencias: npm install.
  4. Iniciar servidor: npm run dev (escucha en http://localhost:3000 generalmente).
  5. Verificar que no haya errores en consola.

🗄️ Base de datos MySQL

Se necesita una base de datos relacional (ej. happy_pets_db) con tablas para clientes, mascotas, productos, citas, usuarios, etc. Configurar las credenciales en el archivo .env del backend.

🔗 Configuración de la API URL en el frontend:
El archivo src/service/API.js contiene la variable base. Ajusta según la URL que genere el backend: 
const API_BASE = (import.meta.env.VITE_API_URL || 'http://localhost:3000').replace(/\/$/, '');
Si usas túneles o IPs diferentes, actualiza esta línea o la variable de entorno VITE_API_URL.
Recuerda: Revisa el README.md del backend para instrucciones detalladas sobre la configuración de la base de datos y migraciones.

Objetivo del sistema

Desarrollar un sistema web para la veterinaria HAPPY PETS que permita gestionar clientes, mascotas, productos, citas y las operaciones diarias. El sistema debe ser:

  • Fácil de usar y eficiente.
  • Seguro y escalable.
  • Permitir a los empleados registrar clientes y mascotas, gestionar productos y servicios, programar citas y llevar control operativo.
  • Adaptable para futuras funcionalidades sin afectar la estabilidad.

Como funciona el sistema (Version 1.0)

Al ingresar a la aplicacion, el usuario visualiza una pantalla inicial con el titulo Happy Pets. Luego es redirigido al login para autenticarse y acceder a su panel segun el rol.

Flujo de ingreso:
  1. Pantalla de carga inicial.
  2. Redireccion a login.
  3. Validacion de credenciales.
  4. Acceso al panel segun rol.
  5. En caso de credenciales invalidas, se muestra mensaje de error y se permite reintentar.

En la interfaz principal el usuario dispone de menu de hamburguesa en la parte superior izquierda y boton para cerrar sesion en la parte inferior.

Roles del sistema

El sistema contempla distintos perfiles: administrador, doctor y secretaria. Cada uno tiene permisos y vistas especificas.

Administrador

  • Acceso completo a usuarios, productos, clientes, mascotas y citas.
  • Puede crear, editar y eliminar registros administrativos.
  • Gestiona el inventario y visualiza alertas de stock bajo.
  • Cuenta con botones de volver y administrar productos en vistas clave.
En desarrollo: eliminacion y edicion avanzada de algunos modulos (clientes, mascotas, usuarios y citas) aun se encuentran en evolucion.

Doctor

  • Gestion de clientes, mascotas y citas.
  • Creacion de citas y apertura de consultas medicas.
  • Puede agregar productos a la consulta y aplicar decremento de stock.
  • Puede crear clientes con mascotas desde su flujo clinico.
En citas, el doctor puede editar datos, refrescar informacion, iniciar consultas y volver al panel principal desde acciones rapidas de interfaz.

Secretaria

  • Modulo en desarrollo para gestion de clientes, mascotas, citas y productos.
  • Se proyecta incorporar control de pagos, reportes y notificaciones de agenda.

Componentes reutilizables

La aplicacion utiliza componentes compartidos para mantener consistencia visual y acelerar el desarrollo de nuevas funcionalidades.

UI y modales

  • AlertModal.jsx: mensajes de alerta y confirmacion.
  • DeleteModal.jsx: confirmacion previa a eliminar.
  • GeneralStyles: estilos comunes de botones y formularios.

Navegacion y listas

  • MenuHamburguesa.jsx: menu lateral por rol.
  • ProductFilter.jsx: filtros por categoria/precio/nombre.
  • ProductList.jsx: listado de productos reutilizable.

Soporte funcional

  • HistoryTable.jsx: historial de movimientos.
  • SpinerLoader.jsx: indicador de carga global.
  • songHelper.js: reproduccion de notificacion sonora al ingresar.

Logica del sistema

La capa logica se divide en hooks personalizados, servicios de API y utilidades para desacoplar la interfaz de la logica de negocio.

Hooks personalizados

  • ClientAndPets.js: creacion y gestion de clientes/mascotas.
  • CreatedCita.js: logica de creacion de citas.
  • DeleteProducto.js: eliminacion de productos.
  • ExpireCitas.js: manejo de vencimiento/estado de citas.
  • GetCitas.js: obtencion de citas desde backend.
  • UsePolling.js: refresco periodico de datos en tiempo real.

Servicios

  • API.js: centraliza peticiones HTTP y la comunicacion frontend-backend.
  • Incluye autenticacion, manejo de errores, operaciones CRUD y endpoints clinicos.

Utilidades

  • songHelper.js: sonido de ingreso y helpers de reproduccion.
La arquitectura modular permite agregar nuevas funciones sin afectar estabilidad general, manteniendo escalabilidad y mantenibilidad del sistema.

                                COMO FUNCIONA EL SISTEMA

                                        Version 1.0

Ingreso = {

    Al ingresar a la aplicacion, el usuario es recibido con una pantalla de inicio que muestra el titulo "Happy Pets 🐶" mientras se carga la aplicacion.

Una vez que la aplicacion se ha cargado completamente, el usuario es redirigido a la pagina de login, donde puede 
ingresar sus credenciales para acceder al sistema.

Si el usuario ingresa credenciales validas, es redirigido a la pagina principal del sistema, donde puede acceder a las diferentes funcionalidades 
de la aplicacion, como gestionar clientes, mascotas, productos, citas, etc.

Si el usuario ingresa credenciales invalidas, se muestra un mensaje de error indicando que las credenciales son incorrectas y se le permite intentar nuevamente.

}

Al Usuario ingresar en su interfaz, tendra un menu de hamburguesa en la parte superior izquierda, 
el cual al hacer clic se despliega un menu de navegacion con las diferentes secciones del sistema segun su ROL.

En la parte de abajo esta un boton para el usuario cerrar sesion, el cual al hacer clic, cierra la sesion del usuario y lo redirige a la pagina de login.

Roles = {

  EL sistema tiene diferentes roles de usuario, como administrador, doctor y recepcionista, 
  cada uno con diferentes niveles de acceso y permisos para realizar ciertas acciones dentro de la aplicacion.

  Administrador =  {

    El administrador tiene acceso completo a todas las funcionalidades del sistema, incluyendo la gestion de usuarios, 
    productos, clientes, mascotas, citas, etc.
    El administrador puede crear, editar y eliminar usuarios, productos, clientes, mascotas y citas.
    El administrador puede ver reportes y estadisticas sobre el funcionamiento de la veterinaria.

    El interfaz del administrador esta diseñada para ser intuitiva y facil de usar, con acceso rapido a las 
    funcionalidades mas importantes y una organizacion clara de las diferentes secciones del sistema.

    El administrador es responsable de mantener el sistema actualizado y seguro, asegurando que solo los usuarios autorizados 
    tengan acceso a las funcionalidades del sistema.

    Al ingresar a su interfaz en la pagina principal, en la parte superior izquierda, 
    el administrador puede ver un menu de navegacion con las diferentes secciones del sistema, como "Clientes", "Mascotas", "Productos", "Citas", etc.
    Al hacer clic en cada seccion, el administrador puede acceder a las funcionalidades relacionadas con esa seccion, 
    como crear nuevos editar productos, etc.

    Al ingresar al interfaz de "Ver Productos", el administrador puede ver una lista de todos los productos disponibles,
    estos tendran la opcion de filtrar por categoria, buscar por nombre o precio.

    En la parte superior derecha, existen 2 botones los cuales sirven para = {
        1- VOLVER : sirve para volver a la pagina principal del sistema, donde el administrador puede acceder a otras secciones del sistema.
        2-Administar Productos: sirve para acceder a la seccion de gestion de productos, donde el administrador puede crear nuevos productos,
         editar productos existentes o eliminar productos.
    }

    Administrar Productos = {

        Al ingresar a la seccion de "Administrar Productos", el administrador puede ver una lista de todos los productos disponibles, 
        con opciones para editar o eliminar cada producto.

        El administrador puede hacer clic en el boton "Editar" para modificar los detalles de un producto existente, como el nombre, 
        la descripcion, el precio, etc.

        El administrador puede hacer clic en el boton "Eliminar" para eliminar un producto existente del sistema.

        El administrador puede hacer clic en el boton "Crear Nuevo Producto" para agregar un nuevo producto al sistema, 
        ingresando los detalles del producto como el nombre, la descripcion, el precio, etc.

    }

    Funciones logicas = {
        El sistema implementa funciones logicas para manejar la creacion, edicion y eliminacion de productos, clientes, mascotas, citas, etc.

        Estas funciones se comunican con el backend a traves de solicitudes HTTP utilizando Axios, para realizar las operaciones necesarias 
        en la base de datos y actualizar la interfaz del usuario en consecuencia.

        El sistema maneja errores y validaciones para asegurar que los datos ingresados por el usuario sean correctos y que las operaciones se realicen de manera segura y eficiente.

        El sistema implementa una arquitectura modular y escalable, permitiendo la adición de nuevas funcionalidades en el futuro sin afectar la estabilidad del sistema.

        El sistema cuenta con una funcion POLLING que se ejecuta cada 20 segundos para actualizar la lista de productos en tiempo real, 
        asegurando que el administrador siempre tenga la informacion mas actualizada sobre los productos disponibles en la veterinaria.

        EL sistema en la lista de productos, muestra el stock disponible de cada producto, y si el stock es menor a 5 unidades, 
        se muestra un mensaje de alerta indicando que el producto esta por agotarse,
        para que el administrador pueda tomar las medidas necesarias para reabastecer el producto y evitar quedarse sin stock.

  Doctor = {
    El doctor tiene acceso a funcionalidades relacionadas con la gestion de clientes, mascotas y citas, pero no tiene acceso a la gestion de usuarios ni productos.

    El doctor puede crear nuevos clientes y mascotas, editar los detalles de los clientes y mascotas existentes, y programar citas para los clientes.

    El doctor puede ver la informacion de los clientes y mascotas, como el historial de citas, tratamientos realizados, etc.

    El doctor es responsable de brindar una atencion de calidad a los clientes y sus mascotas, asegurando que se cumplan las necesidades y expectativas de los clientes.

    Al ingresar a su interfaz en la pagina principal, en la parte superior izquierda, 
    el doctor puede ver un menu de navegacion con las diferentes secciones del sistema, como "Clientes", "Mascotas", "Citas", etc.
    Al hacer clic en cada seccion, el doctor puede acceder a las funcionalidades relacionadas con esa seccion, 
    como crear nuevos clientes o programar citas.

    Citas = {

        Al ingresar a la seccion de "Citas", el doctor puede ver una lista de todas las citas programadas, con opciones para editar o eliminar cada cita.

        El doctor puede hacer clic en el boton "Editar" para modificar los detalles de una cita existente, como la fecha, la hora, el cliente, la mascota, etc.

        El doctor puede hacer clic en el boton "Eliminar" para eliminar una cita existente del sistema.

        El doctor puede hacer clic en el boton "Crear Cita" para agregar una nueva cita al sistema,
         ingresando los detalles de la cita como la fecha, la hora, el cliente, la mascota, etc.

        Cada cita tiene la opcion de Empezar consultas, al hacer clic en esta opcion, 
        se muestra redirige a una seccion con la informacion de la cita y un formulario para ingresar los detalles de la consulta, como los sintomas, el diagnostico, 
        el tratamiento recomendado, etc.

        En ese interfaz el Doctor puede crear clientes junto a sus mascotas, 
        para que el cliente y la mascota queden registrados en el sistema, y luego programar una cita para esa mascota con el doctor.

        En esa interfaz existe un boton para actualizar la informacion de la cita en tiempo real,
        para que el doctor pueda ver cualquier cambio que se realice en la cita, como cambios en la fecha, hora, cliente, mascota, etc.

        existe un boton para regresar a la pagina principal del sistema, donde el doctor puede acceder a otras secciones del sistema.

        en cada cita existe un boton para eliminar la cita, pero esta funcion aun esta en desarrollo y se implementara en futuras actualizaciones del sistema.

    }

        El sistema cuenta con un sistema de decremento de productos al ingresar uno o mas productos en la consulta.

        El doctor tiene la opcion de agregar productos o no segun sea el caso de la cita.

  }
